## 1. 三速度闭环(在 Node 主进程内)

| 闭环 | 频率 | 职责 | 能否打断别人 | 断点 |
|---|---|---|---|---|
| **L1 反射 / 安全包络** | 目标 tick 级;最坏检测延迟见 §1.1 | 危险检测、**预测式**可行性拦截、紧急退出 | **可打断 L2(在可中断点,见 §4.1)**;L2 不能打断它 | — |
| **L2 任务执行器** | 事件/步级 | 跑动作与模板:前置检查→派发→等终态→验证→重试/修复 | 可打断 L3 的等待 | 步边界 + 可中断动作 |
| **L3 LLM 规划** | 慢 | 目标/方法选择、失败后重规划、技能生成 | 不直接控制身体 | — |

- L1/L2 常驻;L3 只在**起点**与**交还**时介入(不逐 tick)。
- 三者共用**同一份事实**(§14 snapshot/events),规划推演不得进入事实层。

### 1.1 延迟预算(安全时序,必须闭合)
- 检测延迟 = `min(事件驱动到达时间, 定时器周期)`;**最坏 = 定时器周期**。
- 1 tick ≈ 50ms(20 TPS)。若用 **100ms 定时器**,最坏检测延迟 ≈100ms ≈**2 tick**;
  要 ~1 tick 需 50ms 定时器或以事件驱动为主(headless bot 无客户端帧率约束,可行)。
- 承诺的"安全停止延迟上限" = 检测延迟 + 决策 + 停止执行确认(§4.2);**必须给出具体 ms/tick 数**。
- HTTP 轮询模型下以"事件到达"计,不会比定时器更差,但网络抖动要计入。

## 2. 身体控制权(单执行分支)

- 定义唯一 `Body` 互斥:任何时刻只有一个"移动/视角/手持/界面"动作在执行。
- **优先级拍卖**(TaskQueue):
  `P0 反射/生存 > P1 用户任务 > P2 组合子任务 > P3 空闲行为`。
- L1 触发 → 请求中断当前 L2 动作;**只能在可中断点抢占**(见 §4.1),不可中断阶段需等其结束
  (等待 ≤ 该阶段 timeout,受 §1.1 延迟预算约束)→ 走 §4 中断流程 → 处理完再交还。
- 只读查询(感知)可与身体并行,不占 Body。

## 3. 动作派发管线(单步)

```text
for step in steps:
  if cancelled/paused: handle
  1. 前置检查:contract.preconditions + step 参数解析($VAR,$prev)
  2. 可行性/安全包络(L1):若预测不安全 → blocked(不派发)
  3. 记录 action_id/start_tick/causal_scope
  4. 派发到 Mineflayer;等终态(成功/超时/事件)
  5. 验证(§13):pass / fail / ambiguous / unobservable
  6. 按 status:
       pass → 下一步
       fail/ambiguous → 安全重试(仅 idempotent)→ 局部修复 → 否则交还
       unobservable → 补观测后重判,或交还
       blocked → 交还
```

## 4. 中断语义(在可中断点;每动作声明)

触发源:L1 安全包络、用户/上层 `task_stop`、超时、失去观测。

### 4.1 动作阶段与可中断点(与 `13` 的 `interruptible` 对齐)
- 动作分阶段:`prepare`(解析目标/站位)→ `execute`(按键/交互/寻路)→ `settle`(生效/落地)。
- **可中断性逐阶段声明**(不是整动作 bool):`prepare`/`settle` 默认可中断;
  `execute` 视动作——寻路/挖掘可中断,蓄力/持续使用需先 `release`。
- **抢占只能在可中断点**;不可中断阶段要等到该阶段结束。
- 因此"任意点中断"应表述为"**在任意可中断点中断**"。

### 4.2 停止确认与超时后的未知
- `safe_stop` 发出后需**确认控制释放**(Mineflayer 回执 + 服务端状态:无继续运动/无继续破坏);
- 在 `stop_confirm_timeout` 内未确认 → 标记 `control_uncertain`,**停止一切新步骤**,交还并报告;
- 超时/中断后**在途效果未知** → `control_status=uncertain`,`effect_status` 不得为 `pass`。

流程:
```text
request_stop(reason):
  1. 停止派发新步骤
  2. 对在途动作执行 safe_stop:
       release_control(停止按键/停止寻路)
       | finish_landing(完成落地/退出水/脱离载具)
       | recall(召回)
  3. 核对在途效果(用 §13 因果签名;可能已部分生效,记为实际进度)
  4. 释放 Body;忽略迟到回调(动作所有权)
  5. 交还 L3:带 {原因, 已完成, 未尝试, 疑似部分生效, 证据}
```
- **中断 ≠ 回滚**:已消耗物/已改世界是实际进度(framework §8)。
- 不可逆长链可先取**检查点**(仅实验/训练场能力,默认关)。

## 5. 安全:预测式包络 vs 后置监视

| | 预测式包络(L1) | 后置监视(L1/L2) |
|---|---|---|
| 时机 | 动作**前** | 动作**后** / 持续 |
| 作用 | **阻止**危险动作(拦截) | 发现违约 → 触发中断交还 |
| 例 | 下方岩浆/悬崖、落脚不支撑、敌对贴脸、背包无武器 | hp 骤降、着火、卡住、无进展 |

- 连续不变量三类(§13):安全 / 进展 / 终止,由 L1 以 tick 级求值;
- 违反 → §4 中断 + 交还,而不是"让它继续然后报失败"。

## 6. 局部修复(仅在原目标/约束内)

失败或 ambiguous 时的阶梯:
1. **安全重试**:仅 `effect_class=idempotent` 且 `status` 为瞬时类;否则不重试(尤其 irreversible/consumable)。
2. **重新定位(local repair)**:在当前世界重新解析该步目标(如"最近的橡木原木"),换站位/目标后**重试一次**;对齐 agent-gavel `_try_repair`(换锚点)。
3. **降级交还**:仍不行 → 交还 L3,带结构化原因(§13 `ActionResult`)与 diff。

> 非幂等动作修复会"真的再做一次",必须有其后置断言兜底,否则宁可放弃(对齐 agent-gavel 的安全约束)。

## 7. 模板执行 = 目标条件化(非字面重放)

- 进入模板时:重新核对 `preconditions` 与**仍成立的子目标**,只补齐缺失部分;不按上次步号继续。
- 中断后恢复:以当前世界为准重建步骤;
- **整体后置**:即使每步曾成功,结束仍要整体验收(环境可能已改变)。
- 组合动作内部循环必须有**有界重复**(count/timeout/budget),防死循环;进展不变量兜底。
